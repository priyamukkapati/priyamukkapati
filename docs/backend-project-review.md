# Backend hiring review

Reviewed the current README, app.py, and tests/test_app.py in StreamCommerce, LiveStream, and CreatorPulse on 2026-10-14. This ordering is an engineering judgment for general early-career backend interviews, not a prediction of interview invitations. All three are small local prototypes.

## Relative hiring value

1. **StreamCommerce** is the strongest general backend example: integer money representation, database constraints, idempotency, conflicting retry rejection, and revenue aggregation provide concrete correctness discussion. Existing tests already check identical retries, conflicting payloads, unchanged totals, and negative amounts. Its highest-value gap is correctness across independent writers and restart, not another sequential retry example.
2. **LiveStream** is a good second example for async interfaces, fan-out, bounded memory, and explicit loss policy. Its current test already fills a queue, verifies the oldest message is discarded, and rejects a banned publisher. It is not yet networked: asyncio.Queue alone does not prove concurrent clients, WebSocket delivery, or scheduling under load.
3. **CreatorPulse** adds algorithmic breadth with deterministic Top-K selection, followed-user filtering, and a deduplicated outbox. Existing tests already cover ranking, exclusions, k=0, repeated events, and conflicting event payloads. Rule-based ranking and an in-memory dictionary provide less general backend evidence than persistent transactions or network behavior. For recommendation-heavy roles it can move up the ordering once quality is evaluated.

## Effort priority

Deepen StreamCommerce first, then add network evidence to LiveStream, then evaluate CreatorPulse. Each demo should have one command, assertions on correctness, recorded workload/environment, and raw results. Do not add a second language, broker, Kubernetes deployment, or an AI feature solely to increase the technology list. The Java projects added alongside these prototypes are distinct exercises, not evidence that the Python projects now implement Java services.
